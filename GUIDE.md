# 🧭 Beginner's Guide — Personal Finance Tracker

This guide assumes **zero tech experience**. Follow every step in order. Don't skip anything.
Text inside grey boxes like `this` is something you **type or copy exactly**.

> 💡 A "terminal" is a window where you type commands. In VS Code you open one from the top menu: **Terminal → New Terminal**.

---

## PART A — Install the tools (one time only, ~20 min)

### Step 1: Install Node.js
Node.js lets your computer run JavaScript (our backend uses it, and it also installs packages).

1. Go to **https://nodejs.org**
2. Download the button that says **LTS** (the "recommended" version).
3. Open the downloaded file and click **Next → Next → Install** (keep all default options).
4. Check it worked: open **Command Prompt** (Windows: press the Windows key, type `cmd`, press Enter) and type:
   ```
   node -v
   ```
   You should see something like `v22.x.x`. ✅ If you see a number, it worked.

### Step 2: Install VS Code (code editor)
1. Go to **https://code.visualstudio.com** → Download → install with default options.
2. Open VS Code.

### Step 3: Install Git (needed later to put your project online)
1. Go to **https://git-scm.com/downloads** → download for your system → install with default options (just keep clicking Next).

## PART C — Create the free online database (MongoDB Atlas, ~10 min)

Your app needs somewhere to store users and transactions. MongoDB Atlas gives you a free one.

### Step 6: Make the database
1. Go to **https://www.mongodb.com/cloud/atlas/register** and sign up (you can use Google).
2. When asked to create a cluster, choose the **Free** option (called M0). Pick any provider and a region close to you (e.g. Mumbai). Click **Create**.
3. **Create a database user** (it may pop up automatically, or go to **Security → Database Access → Add New Database User**):
   - Username: `financeuser`
   - Password: click **Autogenerate** and **copy the password into Notepad**. (Avoid symbols like `@ : / ?` in the password — autogenerated ones are fine.)
   - Click **Create User**.
4. **Allow connections from anywhere** (go to **Security → Network Access → Add IP Address**):
   - Click **Allow Access from Anywhere** (it fills in `0.0.0.0/0`) → **Confirm**.
   - (This is needed so Render can reach your database later.)
5. **Get your connection string**:
   - Go to **Database** (or **Clusters**) → click **Connect** on your cluster → choose **Drivers**.
   - Copy the string. It looks like:
     ```
     mongodb+srv://financeuser:<db_password>@cluster0.abcde.mongodb.net/?retryWrites=true&w=majority&appName=Cluster0
     ```
   - Paste it into Notepad and make two changes:
     1. Replace `<db_password>` (including the `< >`) with your real password.
     2. Add the database name `financetracker` right after `.net/`, like this:
     ```
     mongodb+srv://financeuser:YourPassword123@cluster0.abcde.mongodb.net/financetracker?retryWrites=true&w=majority&appName=Cluster0
     ```
   - ✅ Keep this — it's your **MONGO_URI**.

## PART D — Run the app on your computer

You will run **two things at the same time**: the backend and the frontend. Each needs its own terminal.

### Step 7: Set up and start the BACKEND
1. In VS Code: **Terminal → New Terminal**.
2. Type these commands one at a time, pressing Enter after each:
   ```
   cd server
   ```
   ```
   npm install
   ```
   (Wait 1–2 minutes. Warnings in yellow are fine.)
3. Create your secret settings file:
   - In the left sidebar, open the `server` folder, right-click `.env.example` → **Copy**, then right-click the `server` folder → **Paste**.
   - Rename the copy to exactly `.env` (right-click → Rename). Nothing before the dot!
   - Open `.env` and edit it:
     ```
     MONGO_URI=paste-your-connection-string-from-Step-6-here
     JWT_SECRET=mySuperSecretKey_2026_change_me_to_something_long
     PORT=5000
     CLIENT_URL=http://localhost:5173
     ```
   - Save with **Ctrl + S**.
4. Start the backend:
   ```
   npm run dev
   ```
   ✅ You should see:
   ```
   ✅ MongoDB connected: ...
   🚀 Server running on http://localhost:5000
   ```
5. Test it: open your browser and go to **http://localhost:5000** — you should see `Finance Tracker API is running`.

**Leave this terminal running.** Don't close it.

### Step 8: Set up and start the FRONTEND
1. Open a **second** terminal: click the **+** icon in the terminal panel (or Terminal → New Terminal).
2. Type:
   ```
   cd client
   ```
   ```
   npm install
   ```
3. In the `client` folder, copy `.env.example` and rename the copy to `.env` (same as before). Its content should be:
   ```
   VITE_API_URL=http://localhost:5000/api
   ```
4. Start the frontend:
   ```
   npm run dev
   ```
   ✅ You'll see `Local: http://localhost:5173/`
5. Open **http://localhost:5173** in your browser. 🎉 **Your app is running!**

### Step 9: Try it out
1. Click **Create an account**, sign up.
2. Add a few incomes (Salary) and expenses (Food, Rent…). Pick different dates and months.
3. Watch the cards, pie chart and bar chart update instantly.
4. Try the **Filters**, **Delete (🗑)**, **Export CSV**, the **🌙 dark mode** button, and **Logout**.
5. Make the browser window narrow (or press F12 → phone icon) to see the mobile layout.

**To stop the app:** click in each terminal and press **Ctrl + C**.
**To start it again later:** open the folder in VS Code, then run `cd server` + `npm run dev` in one terminal and `cd client` + `npm run dev` in another.

## PART F — Put your app online (Deployment, ~20 min)

### Step 11: Deploy the BACKEND on Render
1. Go to **https://render.com** → sign up with your GitHub account.
2. Click **New +** → **Web Service** → connect your `finance-tracker` repository.
3. Fill in:
   | Setting | Value |
   |---|---|
   | Name | `finance-tracker-api` |
   | Root Directory | `server` |
   | Runtime | Node |
   | Build Command | `npm install` |
   | Start Command | `npm start` |
   | Instance Type | **Free** |
4. Under **Environment Variables**, add:
   | Key | Value |
   |---|---|
   | `MONGO_URI` | your connection string (same as in your `.env`) |
   | `JWT_SECRET` | the same long secret text |
   | `CLIENT_URL` | `http://localhost:5173` (we'll update this in Step 13) |
5. Click **Create Web Service**. Wait for "Live" (a few minutes).
6. Copy your backend URL from the top, e.g. `https://finance-tracker-api.onrender.com`. Open it — you should see the "API is running" message. ✅

> ⏳ On the free plan, the backend "sleeps" after ~15 minutes of no use. The first request after that can take ~50 seconds. This is normal.

### Step 12: Deploy the FRONTEND on Vercel
1. Go to **https://vercel.com** → sign up with GitHub.
2. Click **Add New → Project** → **Import** your `finance-tracker` repository.
3. Settings:
   - **Root Directory**: click **Edit** → choose `client`.
   - **Framework Preset**: Vite (usually detected automatically).
   - **Environment Variables**: add
     - Key: `VITE_API_URL`
     - Value: your Render URL + `/api`, e.g. `https://finance-tracker-api.onrender.com/api`
4. Click **Deploy**. When it's done, you get a URL like `https://finance-tracker-xyz.vercel.app`. Copy it.

### Step 13: Connect them together
1. Go back to **Render** → your service → **Environment**.
2. Change `CLIENT_URL` to your Vercel URL (no slash at the end), e.g.:
   ```
   https://finance-tracker-xyz.vercel.app
   ```
   (To allow both local and live, separate with a comma: `http://localhost:5173,https://finance-tracker-xyz.vercel.app`)
3. Save → Render redeploys automatically.
4. Open your Vercel URL, sign up, and use your app live! 🚀 Share this link on your resume/LinkedIn.

### Step 14: Updating later
Whenever you change code:
```
git add .
git commit -m "describe what you changed"
git push
```
Render and Vercel automatically rebuild with the new code.

## 🆘 Troubleshooting

| Problem | Fix |
|---|---|
| `'npm' is not recognized` | Node.js isn't installed, or VS Code was open during install. Install Node (Step 1), then **close and reopen VS Code**. |
| `MONGO_URI and JWT_SECRET must be set` | Your `.env` file is missing or misnamed. It must be called exactly `.env` and be inside the `server` folder. |
| `MongoDB connection error: bad auth` | Wrong password in MONGO_URI. Check you removed `< >` around the password. Reset the password in Atlas → Database Access if needed. |
| `MongoDB connection error ... timed out` / `whitelist` | In Atlas → Network Access, add `0.0.0.0/0` (Step 6.4). |
| Website says "Cannot reach the server" | The backend isn't running. Check the first terminal shows "Server running". |
| `CORS blocked for origin` in backend logs | `CLIENT_URL` doesn't exactly match the website address. Fix it in `.env` (local) or Render (live), no trailing `/`. |
| Port already in use (`EADDRINUSE`) | The app is already running in another terminal. Close it with Ctrl + C. |
| Live site: login spins for ~1 minute | Render free plan waking up. Wait and try again. |
| Vercel page shows 404 on refresh | Make sure `client/vercel.json` was pushed to GitHub. |
| Changed `.env` but nothing changed | Stop (Ctrl + C) and start again with `npm run dev`. For Vercel, redeploy after changing env vars. |

## 🗺 How the code is organised (read this to understand + explain in interviews)

```
finance-tracker/
├── server/                      ← BACKEND (Node + Express + MongoDB)
│   ├── server.js                ← Starting point: loads .env, connects DB, starts server
│   ├── app.js                   ← Express setup: CORS, JSON, routes, error handlers
│   ├── config/db.js             ← Connects to MongoDB Atlas
│   ├── models/
│   │   ├── User.js              ← User shape + password hashing (bcrypt)
│   │   └── Transaction.js       ← Transaction shape (type, amount, category, date, notes)
│   ├── controllers/             ← The actual logic for each request
│   │   ├── authController.js    ← register, login, getMe
│   │   └── transactionController.js ← list (with filters), add, update, delete
│   ├── routes/                  ← Which URL calls which controller
│   └── middleware/
│       ├── authMiddleware.js    ← "protect": checks the JWT token
│       └── errorMiddleware.js   ← Turns errors into clean messages
│
└── client/                      ← FRONTEND (React + Tailwind + Recharts)
    └── src/
        ├── main.jsx             ← Starting point: Router, Auth provider, toasts
        ├── App.jsx              ← Pages / routes (login, register, dashboard)
        ├── api/axios.js         ← Talks to backend, adds token automatically
        ├── context/AuthContext.jsx ← Remembers who is logged in (Context API)
        ├── pages/               ← Login, Register, Dashboard
        ├── components/          ← Reusable pieces: Navbar, StatsCards, TransactionForm,
        │                          TransactionList, Filters, Charts, ProtectedRoute
        └── utils/format.js      ← Currency/date formatting, categories, totals, CSV export
```

### API endpoints
| Method | URL | What it does | Login needed |
|---|---|---|---|
| POST | `/api/auth/register` | Create account, returns token | No |
| POST | `/api/auth/login` | Log in, returns token | No |
| GET | `/api/auth/me` | Current user info | Yes |
| GET | `/api/transactions` | List your transactions (filters: `type`, `category`, `startDate`, `endDate`) | Yes |
| POST | `/api/transactions` | Add a transaction | Yes |
| PUT | `/api/transactions/:id` | Edit a transaction | Yes |
| DELETE | `/api/transactions/:id` | Delete a transaction | Yes |

### How login works (JWT) — in simple words
1. You sign up/log in → backend checks password (stored scrambled with bcrypt) → sends back a **token** (like a signed entry pass valid for 7 days).
2. Frontend saves the token in the browser (`localStorage`).
3. Every request sends the token in a header: `Authorization: Bearer <token>`.
4. Backend's `protect` middleware checks the token. Valid → continue; invalid → "401 Not authorized".
5. Every database query includes `user: req.user._id`, so users only ever see **their own** data.
6. Logout simply deletes the token from the browser.

### Small changes you can make yourself
- **Change currency** (₹ → $): in `client/src/utils/format.js` change `LOCALE` to `"en-US"` and `CURRENCY` to `"USD"`.
- **Add/remove categories**: edit the `CATEGORIES` list in the same file.
- **Change the main colour**: search for `emerald` in the client files and replace with e.g. `indigo` or `violet`.

### Interview talking points
- "I used **JWT** for stateless auth and a **middleware** to protect routes; every query is scoped to the logged-in user so data can't leak between users."
- "Passwords are hashed with **bcrypt** in a Mongoose pre-save hook and never returned by the API."
- "I followed a **routes → controllers → models** structure with a central error handler."
- "Charts are computed with `useMemo` from the same filtered list, so filters, cards and charts always stay in sync."
- "Delete is **optimistic** — the UI updates first and rolls back if the API fails."
- "Secrets live in **environment variables**; the frontend is on Vercel and the API on Render, connected via CORS."
